Smallest practical architecture

  1. Local execution: use Codex’s native permission profile with one project checkout as the writable root, minimal system reads, outside reads denied, and command network disabled. Keep temporary directories only if the workflow needs them.
  2. Connectors: disable apps and write tools the workflow does not need. Allow only named reads; keep GitHub fetch read-only where possible. Require user review for each required mutating tool, then verify a decline has no provider effect before relying on the setting. Do not change live settings until separately authorized.
  3. Roles and plans: keep coordinator ownership, builder scope, auditor independence, plans, and acceptance criteria in versioned project rules. Use separate Codex tasks with different permission profiles when roles need different file rights. Keep plan paths read-only for builder tasks and protect shared branches with review.
  4. External actions: do not route around Codex’s connector controls. If a direct connector remains callable without the required gate, leave that action manual. Build an external broker only if it can hold credentials and prevent direct connector access.
  5. Audit and recovery: use Git and pull-request history for code. Add a separate protected action log only if consequential provider actions become automated. Pair it with provider-specific idempotency and recovery steps.
